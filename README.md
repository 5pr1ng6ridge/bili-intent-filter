# B站意图过滤器

输入你想看什么、不想看什么，插件给页面上的视频、直播、课程、番剧等卡片打一个 0~1 的相关度分数，低于阈值的卡片会被模糊；鼠标悬停可以临时查看。视频会额外拉取 B 站标签一起交给模型。另外可以按关键词、按内容类型直接屏蔽（0 分），这部分在本地完成，不调用模型。

## 安装

1. 打开 `chrome://extensions`（Edge 用 `edge://extensions`），开启“开发者模式”
2. 点“加载已解压的扩展程序”，选择本目录
3. 点工具栏里的插件图标 →“⚙ 设置”，填写模式和决策模型

## 日常使用

工具栏弹窗只放日常要用的东西，不显示意图、关键词、Key 等具体设置：

- 开关
- 选择模式：点一下选中或取消，可以同时用多个，也可以全部取消（这时只按内容类型过滤）
- 调阈值：拖动时当前页面即时预览，松手才保存。选了多个模式时，松手后所选模式的阈值都改成这个值
- 本页统计（共几条、模糊了几条、其中几条是规则命中）和今天的模型用量

其余设置都在设置页里，修改会自动保存。

卡片角标写明分数来源：`0.82 Jev`、`0.67 基线` 是模型分数，`0 关键词`、`0 广告` 是本地规则命中，`?` 是打分失败（失败的卡片不模糊）。鼠标停在视频的角标上可以看到用到的标签。

## 设置

### 模式

每个模式包含：

- **我想看 / 不想看**：交给决策模型判断。两项都留空时，这个模式只按关键词和内容类型过滤，完全不调用模型。
- **屏蔽关键词**：逗号或换行分隔，标题、UP 主或副标题里含有任一关键词就直接 0 分。不区分大小写，用 `/.../` 包起来按正则处理，例如 `/第\d+期/`。
- **阈值**

可以同时使用多个模式（弹窗里点选，或在设置页勾选“使用中”），比如“学习”和“游戏”一起开：

| 项 | 合并方式 |
|---|---|
| 我想看 | 每个模式分别打相关度，取最高的那个。只符合其中一个模式也算相关 |
| 不想看 | 所有模式的内容拆开去重，合成一句交给模型 |
| 屏蔽关键词 | 合并，命中任一个就 0 分 |
| 阈值 | 取最低的那个，免得一个模式想看的内容被另一个模式的阈值挡住 |

### 内容类型

页面上的卡片会被识别成六类，每类可以选“模型打分 / 直接 0 分 / 不处理”，对所有模式生效：

| 类型 | 识别依据 | 默认 |
|---|---|---|
| 视频 | `/video/BV…` 链接 | 模型打分 |
| 直播 | `live.bilibili.com/<房间号>`，首页推荐和楼层里的直播卡、搜索页的直播卡 | 模型打分 |
| 课程 | `/cheese/play/ss…`，课堂楼层、搜索页课程卡和推广大卡、播放页右侧课程卡 | 模型打分 |
| 番剧影视 | `/bangumi/play/…`、`/bangumi/media/…`，楼层卡、搜索页影视卡、空间里的追番 | 模型打分 |
| 广告 | 带广告标记的卡片，或链接指向 `cm.bilibili.com`、`gaoneng.bilibili.com`、带 `creative_id` / `from_bcg` 参数 | 直接 0 分 |
| 其他 | 漫画、专栏、动态 | 不处理 |

### 生效页面

首页、搜索、播放页、分区、UP 主空间等始终生效。历史记录（`/history`）和收藏夹、稍后再看（`space.bilibili.com/<uid>/favlist`、`/medialist/`、`/list/ml…`、`/watchlater`）默认不过滤，可以单独打开。

## 用量

- **本地规则优先**：关键词和类型规则在页面里直接判定，命中的不发给模型。
- **按需打分**：只有滚动到视口附近（上下 800px 内）的卡片才会送去打分。
- **持久缓存**：分数拆成分项缓存在 `chrome.storage.local`。每个“想看”一组，合并后的“不想看”一组，都按“模型配置 + 打分版本 + 是否用标签”区分。刷新页面、切回用过的模式、多个标签页同时打开同一内容都不会重复调用。多选时也能复用：单独用过“学习”和“游戏”之后，两个一起开不用重新打相关度，只有合并后的“不想看”变了才需要补问那一项。改关键词、内容类型、阈值不影响缓存。每组最多 4000 条，最多保留 30 组，超出的按最近使用淘汰；内置基线不缓存。
- **标签缓存**：每个视频的标签只拉一次，最多存 8000 个视频。
- 设置页“用量与缓存”里有当天的请求数、打分条数、缓存命中数，可以一键清除缓存（分数和标签一起清）。

## 决策模型

| 后端 | 说明 |
|---|---|
| Jev | TypeSafe 的决策模型，插件直接调用它的 System One 接口，填 API Key 即可 |
| 自定义 HTTP 接口 | 把卡片信息 POST 给你自己的服务，由它返回分数 |
| 内置基线 | 字面重合度（中文按相邻两字切分）。不懂同义词，只用来跑通流程，以及给外部模型当对照组 |

填好地址和 Key 后可以点“测试连接”，用表单里的值和正在编辑的模式给两个示例标题打分，能看到分数和耗时。自定义地址的访问权限也在这一步申请。

API Key 存在 `chrome.storage.local`，不随浏览器账号同步，只会发送到你填写的接口地址。

### 视频标签

卡片上只有标题和 UP 主，很多标题看不出在讲什么（“第 3 期”“这也太离谱了”）。所以打分前插件会去拿视频的标签，和标题一起交给模型（三种后端都用）。

- 来源是 B 站公开接口 `api.bilibili.com/x/web-interface/view/detail/tag`，不带 Cookie，和你的登录状态无关
- 只有 BV 号的视频才有标签；直播、课程、番剧只用卡片上的信息
- 话题类标签（`#xxx#` 活动话题）跟内容关系不大，会被去掉；每个视频最多取 12 个
- 每个视频只拉一次，存在本机，最多 8000 个
- 最多 6 个并发，单个 4 秒超时。B 站返回风控（412、-352 等）时暂停 5 分钟，期间只用卡片信息打分，不会一直撞接口
- 鼠标停在角标上能看到这条视频用到的标签
- 设置页“决策模型”里可以关掉。开关会切换到另一组缓存，所以切换之后会重新打分

### Jev

接入方式可选 TypeSafe 官方（`https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`）或 OpenRouter（`https://openrouter.ai/api/v1/systemone`，模型 `~typesafe/jev-latest`）。其他字段相同的网关选“自定义”，自己填地址和模型名。

Jev 一次请求只评估一份 `state`，所以插件对每条内容单独发一次请求（最多 6 个并发，遇到 429/529 会等 1.5 秒重试一次）。同时用“学习”和“游戏”两个模式时的请求示例：

```json
{
  "model": "jev-latest",
  "state": {
    "类型": "视频",
    "标题": "从零写一个 Rust Web 框架",
    "UP主": "某UP主",
    "标签": "Rust、编程、后端、Web开发",
    "时长": "32:10"
  },
  "questions": {
    "relevance": {
      "type": "score",
      "instructions": "用户在 B 站上想看的内容是：Rust 入门，系统设计。这条内容和用户想看的内容有多相关？",
      "criteria": ["毫无关系", "碰巧提到相关的词", "涉及一部分或相邻话题", "正是在讲这个主题"]
    },
    "relevance_2": {
      "type": "score",
      "instructions": "用户在 B 站上想看的内容是：单机游戏实况。这条内容和用户想看的内容有多相关？",
      "criteria": ["…同上…"]
    },
    "excluded": {
      "type": "noul",
      "instructions": "用户明确不想看这些内容：八卦，引战，标题党。这条内容属于用户不想看的内容吗？"
    }
  }
}
```

- 每个“想看”问一个 `relevance` / `relevance_2` / …，合并后的“不想看”问一个 `excluded`
- 已经缓存过的分项不再问，所以实际请求里可能只有其中几个问题
- `criteria` 的实际措辞见 `scorers.js` 里的 `RELEVANCE_CRITERIA`
- `state` 里的空字段不发；番剧等内容会多一个 `副标题`，没拿到标签时不发 `标签`

最终分数 = max(`relevance_i.score / 3`) ×（1 − `excluded.noul`），没有“想看”时前一项按 1 算，没有“不想看”时后一项按 0 算。

想调整模型的判断方式，改 `scorers.js` 里的 `RELEVANCE_CRITERIA` 和 `buildJevRequest()`，并把 `SCORER_VERSION` 加一，让旧缓存失效。按官方文档的建议，档位要描述具体情形而不是“比较相关”之类的程度词。

### 自定义 HTTP 接口约定

请求 `POST <接口地址>`，`Content-Type: application/json`。为了能按分项缓存，插件把每个“想看”和合并后的“不想看”分开调用，每次只有 `intent` 和 `exclude` 中的一个有值：

```json
{
  "intent": "Rust 入门，系统设计",
  "exclude": "",
  "items": [
    { "id": "BV1xx411c7mD", "kind": "video", "title": "从零写一个 Rust Web 框架", "up": "某UP主", "sub": "", "duration": "32:10", "tags": ["Rust", "编程"] },
    { "id": "live:545068", "kind": "live", "title": "今晚写编译器", "up": "某主播", "sub": "", "duration": "", "tags": [] }
  ]
}
```

```json
{ "intent": "", "exclude": "八卦，引战", "items": [ … ] }
```

响应格式两种调用一样：

```json
{ "scores": { "BV1xx411c7mD": 0.82, "live:545068": 0.4 } }
```

- 只有 `intent` 时，分数表示和想看的内容有多相关
- 只有 `exclude` 时，分数表示有多**不**属于不想看的内容（1 = 完全不沾边，0 = 正是不想看的）。按“只填了不想看”的模式去打分，返回的数就是这个意思，服务端不用分情况
- 插件计算最终分数：max(各个想看的分数) × 不想看那次的分数
- `kind` 取值：`video` `live` `course` `bangumi` `ad` `other`；视频的 `id` 是 BV 号，其他类型带前缀
- `tags` 是视频标签，拿不到或关掉了标签时是空数组
- 每批最多 30 条，几个分项并行调用，各自 15 秒超时
- 分数范围 0~1；没有返回分数的内容不会被模糊，角标显示 `?`

`server/score_server.py` 是一个只用标准库、实现了上述接口的示例服务，接入模型时只需要改其中的 `score_items()`：

```bash
python server/score_server.py
```

填了 API Key 的话，会以 `Authorization: Bearer <Key>` 发送。

本机地址（`localhost` / `127.0.0.1`）、TypeSafe 和 OpenRouter 不需要额外授权，其他地址要在设置页点一次“测试连接”授权。

## 适配 B 站改版

卡片识别不到时，先在页面上看 `data-bif-kind` 属性（插件会给识别到的卡片加上类型标记）。然后按情况修改：

- **卡片容器、标题、UP 主选择器**：改 `content.js` 顶部的几个常量
- **链接类型规则**：改 `rules.js` 的 `KIND_PATTERNS`
- **历史记录、收藏夹的网址规则**：改 `rules.js` 的 `pageScope()`

## 目前的限制

- 用到的是卡片上的标题、UP 主、副标题、时长，加上视频标签；没有用简介
- 只有视频有标签。屏蔽关键词只匹配卡片上的文字，不匹配标签
- 有些视频带的是商单标签（比如品牌名），B 站接口里它和普通标签是同一种类型，没法区分，只能交给模型自己判断
- 阈值是绝对分数，不同模型的分数分布差别很大，需要先打开分数角标观察一下再调
- 还没有 👍/👎 反馈
